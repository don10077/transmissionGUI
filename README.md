# transmissionGUI

**transmissionGUI** — лёгкий десктопный GUI-клиент для битторент-демона
**Transmission** для Windows, Linux и macOS. Собирается на **C++23 / Qt 6**, общается с демоном
через штатный JSON-RPC-интерфейс.

Вместо веб-интерфейса демона и консольного `transmission-remote` — одно
нативное окно: список торрентов, управление, фильтры и статус сессии.

## Возможности

**Уже работает**

- Подключение к локальному или удалённому демону: HTTP(S), базовая
  аутентификация, самообновление `X-Transmission-Session-Id` (409),
  переезд RPC-пути (301, Transmission 4.x `/web/`), профили, mTLS и
  отменяемое переподключение после временного сбоя;
- Список торрентов: статус, прогресс, размер, скорости ↓/↑, ETA, пиры,
  рейтинг, метки;
- Сортировка по любому столбцу, фильтр по статусу, поиск по имени;
- Управление: запустить / остановить (выбранные и все), удалить
  (с данными на диске или без);
- Отдельные интервалы обновления видимого и свёрнутого окна, опциональное
  сглаживание отображаемых скоростей, суммарный размер видимых или выбранных
  торрентов и версия демона в строке состояния;
- Добавление торрентов: файл `.torrent`, magnet-ссылка, URL; папка загрузки
  со свободным местом на диске, выбор файлов (want/skip), лимит пиров,
  «сохранить как», запуск сразу, последовательное скачивание
  (Transmission ≥ 4.1);
- Повреждённый `.torrent`: при добавлении автоматически исправляются
  распознаваемые ошибки длины текстовых полей и удалённые схемы URL трекеров.
  Исправленная копия передаётся демону в памяти; исходный файл, секция `info`
  и бинарные хеши остаются неизменными. Неизвестную порчу оценивает демон,
  его ошибка показывается обычным способом;
- Перетаскивание `.torrent` и ссылок, открытие `.torrent` и magnet из ОС,
  опциональное добавление из буфера и отслеживаемой папки;
- Группировка в боковой панели по папке, метке или трекеру со счётчиками;
- Трей-иконка: кнопка «Закрыть» сворачивает окно в трей, быстрый
  «Запустить все / Остановить все / Обновить», выход — из меню трея;
- Контекстное меню списка, горячие клавиши (Ctrl+K, Ctrl+O, F5, Del);
- Профили хранят сопоставления путей, историю папок и быстрые лимиты
  загрузки и отдачи. Настройки окна и разделителя сохраняются между запусками;
- Вкладки деталей выбранного торрента: **Файлы** (размер, прогресс,
  приоритет, want/skip-чекбоксы — применяются через `torrent-set`),
  **Пиры** (адрес, клиент, прогресс, скорости), **Трекеры**
  (announce, тир, сидеры/личеры, последний ответ);
- Диалоги свойств и переноса, пакетное редактирование явно выбранных
  свойств и перенос нескольких торрентов одним запросом;
- Двухуровневое окно: список торрентов сверху, снизу — вкладки выбранного
  торрента: **General** (сводка, как в «Свойствах»), **Трекеры**, **Пиры**,
  **Файлы**, **Статистика** (session-stats демона, автообновление).

- Настройки демона и колонок, GeoIP и обратный DNS для пиров;
- Импорт и экспорт резервной копии настроек transmissionGUI в INI,
  перенос списка торрентов как текстового списка magnet-ссылок и ручная
  проверка новых выпусков клиента через меню «Справка».

## Совместимость

| Компонент | Поддержка |
|---|---|
| Transmission **2.x / 3.x / 4.x** | ✅ основной целевой диапазон |
| Legacy JSON-RPC демона (`session-get`, `torrent-get`, …) | ✅ используется клиентом |
| **Transmission ≥ 4.1** — **JSON-RPC 2.0** (`session_get`, `torrent_get`, …) | ✅ выбирается автоматически |

Клиент выбирает JSON-RPC 2.0 по заголовку `X-Transmission-Rpc-Version` от
демона. При подключении к Transmission 4.0.x используется legacy RPC.
[Спецификация Transmission](https://github.com/transmission/transmission/blob/4.1.0/docs/rpc-spec.md)

## Стек

- **C++23**, **Qt 6** (Core, Network, Widgets, SVG);
- **CMake ≥ 3.28** (presets), сборка под Windows через **MSYS2/MinGW64**;
- Автономные тесты **GoogleTest** с локальным мок-сервером и отдельные
  сценарии против живого демона.

```
core/   — RPC-клиент, модели, bencode, утилиты (чистый C++, без UI)
app/    — GUI-приложение (Qt Widgets, русский UI)
tests/  — unit-тесты core + mock-HTTP-сервер
tools/  — tgui_daemon_check: CLI-проверка соединения с реальным демоном
```

## Сборка (Windows, MSYS2 MinGW64)

Для сборки приложения запустите `build.cmd` двойным щелчком: он настроит CMake,
соберёт Debug в `build/win-debug` и оставит окно с результатом открытым.
Перед пересборкой закройте запущенное приложение.

```bat
build.cmd release
build.cmd debug --no-pause
```

По умолчанию используется MSYS2 из `D:\Install\MSYS2`. Для другой установки
задайте переменную `MSYS2_ROOT`. Нужны пакеты MinGW64: CMake, Ninja, GCC,
Qt 6 (включая LinguistTools и `mingw-w64-x86_64-qt6-svg`), zlib и GoogleTest. Скрипт собирает приложение
и по умолчанию запускает автономные тесты.

Нужны: MSYS2 `mingw64` (g++ 16.x), Qt 6 (Core/Network/Widgets/SVG), CMake ≥ 3.28.
Пресеты берутся из `CMakeUserPresets.json` (при отсутствии — скопируйте
`CMakeUserPresets.json.example`).

> ⚠️ Каталог `mingw64/bin` должен быть в `PATH` — иначе AUTOMOC молча не
> запускает `moc.exe`, и сборка падает на этапе линковки.

```powershell
cmake --preset win-debug
cmake --build --preset win-debug --parallel
cmake --preset win-debug --build-and-run test   # unit-тесты
```

Результаты:

- `build/win-debug/app/transmissiongui.exe` — приложение;
- `build/win-debug/tests/tgui_tests.exe` — unit-тесты;
- `build/win-debug/tools/tgui_daemon_check.exe` — быстрая проверка
  соединения с демоном:

  ```
  tgui_daemon_check.exe http://127.0.0.1:9091 --user USER --pass PASS
  ```

## Пакеты

Для portable ZIP под Windows после сборки Release выполните
`powershell -File tools/package-windows.ps1`. Распакуйте
`build/packages/transmissiongui-windows-x64.zip` и запустите
`transmissiongui.exe` из распакованной папки.

Для Ubuntu нужны GCC, CMake ≥ 3.28, Ninja, Qt 6 Base, SVG и Tools, GoogleTest и zlib.
Для создания DEB установите также `dpkg-dev` и `file`.
На macOS эти зависимости можно установить через Homebrew. При конфигурации
передайте `-DCMAKE_PREFIX_PATH="$(brew --prefix qt)"`.

```sh
cmake --preset release
cmake --build --preset release
QT_QPA_PLATFORM=offscreen ctest --preset release
cpack --config build/release/CPackConfig.cmake -B build/packages
```

CPack готовит DEB на Ubuntu и DMG на macOS. Сборку macOS проверяет отдельная
задача GitHub Actions после запуска workflow.

## Быстрый запуск к демону

`transmissiongui-daemon.cmd` (ярлык на рабочем столе
«transmissionGUI (домашний демон)») — запуск с автоподключением
к домашнему демону, без окна диалога.

Или параметры командной строки (тоже автоподключение):

```
transmissiongui.exe --url http://хост:порт [--user имя] [--pass пароль] [--path /transmission/rpc]
```

> ⚠️ В адресе обязательно нужен **порт** (у демона Transmission — 9091):
> `http://192.168.7.10:9091`. Без порта приложение попытается уйти на порт 80
> и получит «Connection refused» (адрес, на который шло подключение,
> теперь показывается в окне ошибки).

## Тесты

Тесты охватывают утилиты форматирования, bencode, парсинг ответов демона,
JSON-RPC транспорт, высокоуровневый RPC-клиент, GUI-модели и панели
(грид с 26 колонками, вкладки Файлы/Пиры/Трекеры, «General», «Статистика»,
раскладка окна). Используется моковый HTTP-сервер RPC-демона — проверяются
аутентификация, handshake session-id (409), редирект RPC-пути (301),
таймауты и ошибки демона.
