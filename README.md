# transmissionGUI

**transmissionGUI** — лёгкий десктопный GUI-клиент для битторент-демона
**Transmission** (Windows). Собирается на **C++23 / Qt 6**, общается с демоном
через штатный JSON-RPC-интерфейс.

Вместо веб-интерфейса демона и консольного `transmission-remote` — одно
нативное окно: список торрентов, управление, фильтры и статус сессии.

## Возможности

**Уже работает**

- Подключение к локальному или удалённому демону: HTTP(S), базовая
  аутентификация, самообновление `X-Transmission-Session-Id` (409),
  переезд RPC-пути (301, Transmission 4.x `/web/`);
- Список торрентов: статус, прогресс, размер, скорости ↓/↑, ETA, пиры,
  рейтинг, метки;
- Сортировка по любому столбцу, фильтр по статусу, поиск по имени;
- Управление: запустить / остановить (выбранные и все), удалить
  (с данными на диске или без);
- Автообновление списка (интервал 2 с), суммарные скорости и версия
  демона в статус-баре;
- Добавление торрентов: файл `.torrent`, magnet-ссылка, URL; папка загрузки
  со свободным местом на диске, выбор файлов (want/skip), лимит пиров,
  «сохранить как», запуск сразу, последовательное скачивание
  (Transmission ≥ 4.1);
- Drag&drop: `.torrent`-файлы и magnet/http-ссылки прямо в окно;
- Группировка списка по папке, лейблу или трекеру (строки-группы с
  суммарным размером и счётчиком);
- Трей-иконка: кнопка «Закрыть» сворачивает окно в трей, быстрый
  «Запустить все / Остановить все / Обновить», выход — из меню трея;
- Контекстное меню списка, горячие клавиши (Ctrl+K, Ctrl+O, F5, Del);
- Настройки соединения сохраняются между запусками.

**В планах** (подробный план — в [WORKFLOW.md](WORKFLOW.md))

- Вкладки: файлы, пиры, трекеры, статистика;
- Настройки демона (alt-speed, блэклист, DHT/PEX/LPD, очереди),
  несколько демонов, настройки колонок;
- Добавление ссылок из буфера, пароль по 401;
- GeoIP-флаги пиров, импорт/экспорт списка.

## Совместимость

| Компонент | Поддержка |
|---|---|
| Transmission **2.x / 3.x / 4.x** | ✅ основной целевой диапазон |
| Legacy JSON-RPC демона (`session-get`, `torrent-get`, …) | ✅ используется клиентом |
| **Новый протокол Transmission ≥ 4.1** — стандартный **JSON-RPC 2.0** (`session_get`, `torrent_get`, …) | 🗓 запланирован (этап 8) |

> В Transmission 4.1+ RPC-интерфейс переведён на стандартный JSON-RPC 2.0
> (snake_case-имена, тело запроса `jsonrpc/params/id`). Старый протокол там
> пока работает через compat-слой, но объявлен deprecated и будет удалён,
> поэтому в планах — нативная поддержка нового протокола с автоопределением
> по демону. Спецификация: `docs/rpc-spec.md` в исходниках демона.

## Стек

- **C++23**, **Qt 6** (Core, Network, Widgets);
- **CMake ≥ 3.28** (presets), сборка под Windows через **MSYS2/MinGW64**;
- unit-тесты на **GoogleTest** с моковым HTTP-сервером RPC-демона (46 тестов).

```
core/   — RPC-клиент, модели, bencode, утилиты (чистый C++, без UI)
app/    — GUI-приложение (Qt Widgets, русский UI)
tests/  — unit-тесты core + mock-HTTP-сервер
tools/  — tgui_daemon_check: CLI-проверка соединения с реальным демоном
```

## Сборка (Windows, MSYS2 MinGW64)

Нужны: MSYS2 `mingw64` (g++ 16.x), Qt 6 (Core/Network/Widgets), CMake ≥ 3.28.
Пресеты берутся из `CMakeUserPresets.json` (при отсутствии — скопируйте
`CMakeUserPresets.json.example`).

> ⚠️ Каталог `mingw64/bin` должен быть в `PATH` — иначе AUTOMOC молча не
> запускает `moc.exe`, и сборка падает на этапе линковки.

```powershell
cmake --preset win-debug
cmake --build --preset win-debug --parallel
cmake --preset win-debug --build-and-run test   # unit-тесты
```

Результаты:

- `build/win-debug/app/transmissiongui.exe` — приложение;
- `build/win-debug/tests/tgui_tests.exe` — unit-тесты;
- `build/win-debug/tools/tgui_daemon_check.exe` — быстрая проверка
  соединения с демоном:

  ```
  tgui_daemon_check.exe http://127.0.0.1:9091 --user USER --pass PASS
  ```

## Быстрый запуск к демону

`transmissiongui-daemon.cmd` (ярлык на рабочем столе
«transmissionGUI (домашний демон)») — запуск с автоподключением
к домашнему демону, без окна диалога.

Или параметры командной строки (тоже автоподключение):

```
transmissiongui.exe --url http://хост:порт [--user имя] [--pass пароль] [--path /transmission/rpc]
```

> ⚠️ В адресе обязательно нужен **порт** (у демона Transmission — 9091):
> `http://192.168.7.10:9091`. Без порта приложение попытается уйти на порт 80
> и получит «Connection refused» (адрес, на который шло подключение,
> теперь показывается в окне ошибки).

## Тесты

46 unit-тестов core: утилиты форматирования, bencode, парсинг ответов демона,
JSON-RPC транспорт, высокоуровневый RPC-клиент. Используется моковый
HTTP-сервер RPC-демона — проверяются аутентификация, handshake session-id
(409), редирект RPC-пути (301), таймауты и ошибки демона.
